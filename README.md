# Сервис обработки перечня «нежелательных организаций» (272-ФЗ)

Сервис ежедневно скачивает файл-первоисточник (xlsx) со страницы Минюста
России, определяет дату актуальности данных, при появлении новой версии
разбирает наименования организаций по правилам, показывает результат
ответственному в веб-интерфейсе и выкладывает целевой CSV в папку, из которой
его забирает существующий скрипт загрузки в CDI.

Реализовано по ТЗ [`TZ_perechen_272FZ.md`](TZ_perechen_272FZ.md).

---

## 1. Состав репозитория

| Каталог | Что внутри |
|---|---|
| [`packages/core`](packages/core) | Чистый Dart: модели, чтение xlsx, правила разбора наименований (п. 6 ТЗ), конвертер в целевой CSV (cp1251), diff версий. Полностью покрыт unit- и golden-тестами. |
| [`apps/server`](apps/server) | Сервис: планировщик (МСК), загрузчик с ретраями, SQLite, REST API, SMTP-уведомления, публикация в папку CDI. |
| [`apps/ui`](apps/ui) | Flutter Web: четыре экрана ответственного (версии, версия, журнал, настройки). Собирается в статику и раздаётся сервером. |
| [`reference`](reference) | Эталонные файлы: `export.xlsx` (первоисточник) и `perechen_organizatsij_272_FZ_2025_03_03.csv` (целевой формат). Используются в golden-тестах. |
| [`scripts`](scripts) | [`build.sh`](scripts/build.sh) и [`build.ps1`](scripts/build.ps1): сборка комплекта поставки для текущей ОС. |
| [`packaging`](packaging) | Установка службы на чистую ОС: [`linux`](packaging/linux) (systemd, deb/rpm через nfpm), [`windows`](packaging/windows) (задача планировщика от SYSTEM), [`macos`](packaging/macos) (launchd). |

        │                                                          │

## 2. Быстрый старт (разработка)

Нужны Dart SDK ≥ 3.5 и Flutter ≥ 3.24 (для UI).

```bash
# 1. Ядро: тесты правил разбора, CSV и golden-тест конвейера
cd packages/core && dart pub get && dart test

# 2. Сервер
cd ../../apps/server && dart pub get && dart test

# 3. Интерфейс
cd ../ui && flutter pub get && flutter test

# 4. Запуск сервера (без планировщика, БД и файлы — во временной папке)
cd ../server
DATA_DIR=/tmp/perechen \
CDI_DROP_DIR=/tmp/perechen/cdi \
COUNTRIES_FILE=../../packages/core/assets/countries_ru.txt \
MINJUST_EXPORT_URL=https://example/export.xlsx \
BASIC_AUTH_USER=admin BASIC_AUTH_PASS=admin \
dart run bin/server.dart

# 5. Интерфейс в режиме разработки (отдельный порт)
cd ../ui
flutter run -d chrome --dart-define=API_BASE=http://localhost:8080/
```

Полезные команды сервера:

```bash
dart run bin/server.dart check-now     # разовая проверка сайта
dart run bin/server.dart publish 1     # опубликовать версию №1
dart run bin/server.dart reparse 1     # перерасбор по уже скачанному файлу
dart run bin/server.dart paths         # какие пути и файлы использует на этой ОС
```

Диагностика разбора на эталонном файле:

```bash
cd packages/core
dart run tool/dump_parse.dart review      # показать записи, требующие проверки
dart run tool/dump_parse.dart nocountry   # записи без распознанной страны
dart run tool/dump_parse.dart all         # весь разбор
```

## 3. Развёртывание (без контейнера)

Сервис ставится системной службой на чистую операционную систему: Windows
Server / 10-11, Debian/Ubuntu/Astra, RED OS/ALT, macOS. На целевой машине не
нужны ни Docker, ни Dart, ни Flutter, ни СУБД — комплект самодостаточен:
скомпилированный сервер, собранный веб-интерфейс, справочник стран, скрипты
установки.

### 3.1. Сборка комплекта

Кросс-компиляции у Dart нет: комплект для каждой ОС собирается **на этой же
ОС**. Dart SDK ≥ 3.5 и Flutter ≥ 3.24 нужны только сборочной машине.

```bash
./scripts/build.sh                       # Linux, macOS
./scripts/build.sh --skip-ui             # только сервер, UI уже собран
```

```powershell
.\scripts\build.ps1                      # Windows
.\scripts\build.ps1 -SqliteDll C:\sqlite3.dll   # своя библиотека SQLite
```

Результат — `dist/perechen-<версия>-<ос>-<арх>/` и архив рядом:

```
bin/perechen[.exe]      сервер и командные операции
lib/                    нативная библиотека SQLite, если положена в комплект
web/                    собранный Flutter Web
assets/countries_ru.txt справочник стран (редактируется на месте)
packaging/              install/uninstall и описание службы для этой ОС
config.example.yaml     образец конфигурации
```

### 3.2. Установка

Скопируйте архив на целевую машину, распакуйте и запустите установщик из
комплекта. Повторный запуск установщика обновляет службу, сохраняя данные и
`config.yaml`.

**Debian / Ubuntu / Astra Linux, RED OS / ALT** (systemd):

```bash
tar -xzf perechen-1.0.0-linux-x64.tar.gz
sudo perechen-1.0.0-linux-x64/packaging/install.sh \
  --cdi-dir /mnt/cdi/inbox --port 8080
sudo nano /etc/perechen/config.yaml      # SMTP, получатели, пароль UI
sudo systemctl restart perechen
```

**Windows Server / 10-11** (консоль PowerShell от имени администратора):

```powershell
Expand-Archive perechen-1.0.0-windows-x64.zip -DestinationPath C:\Temp
C:\Temp\perechen-1.0.0-windows-x64\packaging\install.ps1 -OpenFirewall
notepad C:\ProgramData\Perechen272FZ\config.yaml
Stop-ScheduledTask Perechen272FZ; Start-ScheduledTask Perechen272FZ
```

Windows-служба в привычном виде (`services.msc`) требует от программы
поддержки протокола SCM, которой у консольного бинарника нет, поэтому
установщик регистрирует **задачу планировщика от SYSTEM**: старт при загрузке
ОС без входа пользователя, перезапуск после сбоя — то же поведение, что у
службы. Кому нужна именно запись в `services.msc` — оберните
`bin\perechen.exe` в [WinSW](https://github.com/winsw/winsw) или NSSM,
аргументы те же: `--config <путь к config.yaml>`.

**macOS** (демон launchd):

```bash
tar -xzf perechen-1.0.0-macos-arm64.tar.gz
sudo perechen-1.0.0-macos-arm64/packaging/install.sh
sudo nano /usr/local/etc/perechen/config.yaml
sudo launchctl kickstart -k system/ru.perechen.server
```

### 3.3. Пакеты .deb и .rpm (необязательно)

`install.sh` одинаково работает и в deb-, и в rpm-дистрибутивах, пакет для
этого не нужен. Если по регламенту нужен именно пакет, его собирает
[nfpm](https://github.com/goreleaser/nfpm) из того же комплекта — ни
`dpkg-buildpackage`, ни `rpmbuild` не требуются:

```bash
cd dist/perechen-1.0.0-linux-x64
VERSION=1.0.0 ARCH=amd64 MAINTAINER="ops@corp.example" VENDOR="corp" \
  nfpm package -f packaging/nfpm.yaml -p deb -t ..
VERSION=1.0.0 ARCH=amd64 MAINTAINER="ops@corp.example" VENDOR="corp" \
  nfpm package -f packaging/nfpm.yaml -p rpm -t ..
```

Пакет ставит те же файлы в `/opt/perechen`, заводит пользователя `perechen`,
включает юнит и создаёт `/etc/perechen/config.yaml` при первой установке.

### 3.4. Управление службой

| Действие | Linux | Windows | macOS |
|---|---|---|---|
| состояние | `systemctl status perechen` | `Get-ScheduledTask Perechen272FZ` | `sudo launchctl print system/ru.perechen.server` |
| запуск | `sudo systemctl start perechen` | `Start-ScheduledTask Perechen272FZ` | `sudo launchctl kickstart system/ru.perechen.server` |
| остановка | `sudo systemctl stop perechen` | `Stop-ScheduledTask Perechen272FZ` | `sudo launchctl bootout system/ru.perechen.server` |
| перезапуск | `sudo systemctl restart perechen` | `Stop-…; Start-…` | `sudo launchctl kickstart -k system/ru.perechen.server` |
| журнал | `journalctl -u perechen -f` | `Get-Content C:\ProgramData\Perechen272FZ\logs\perechen.log -Wait -Tail 20` | `tail -f /usr/local/var/perechen/logs/perechen.log` |
| удаление | `sudo /opt/perechen/packaging/uninstall.sh` | `…\packaging\uninstall.ps1` | `sudo /usr/local/perechen/packaging/uninstall.sh` |

Удаление по умолчанию сохраняет данные и настройки; ключ `--purge`
(`-Purge` в PowerShell) удаляет и их.

### 3.5. Обновление

Соберите новый комплект и запустите установщик поверх: он остановит службу,
заменит файлы программы, сохранит `config.yaml`, БД и папку CDI, запустит
службу заново. Откат — установка предыдущего комплекта тем же способом.

### 3.6. Что где лежит

| | Linux | Windows | macOS |
|---|---|---|---|
| программа | `/opt/perechen` | `C:\Program Files\Perechen272FZ` | `/usr/local/perechen` |
| данные, БД | `/var/lib/perechen` | `C:\ProgramData\Perechen272FZ` | `/usr/local/var/perechen` |
| конфигурация | `/etc/perechen/config.yaml` | `C:\ProgramData\Perechen272FZ\config.yaml` | `/usr/local/etc/perechen/config.yaml` |
| папка CDI | `/mnt/cdi/inbox` | `…\Perechen272FZ\cdi-inbox` | `…/perechen/cdi-inbox` |
| журнал | journald | `…\Perechen272FZ\logs\perechen.log` | `…/perechen/logs/perechen.log` |
| от чьего имени | `perechen` | `SYSTEM` | `root` |

Пути задаются при установке (`--data-dir`, `--cdi-dir`, `-DataDir`, `-CdiDir`)
и потом хранятся в `config.yaml`.

### 3.7. Проверка и диагностика

```bash
/opt/perechen/bin/perechen paths --config /etc/perechen/config.yaml
curl -u admin:пароль http://localhost:8080/api/health
```

Команда `paths` печатает всё, что зависит от машины: какой `config.yaml`
подхватился, куда пишутся данные, где ищется библиотека SQLite и что из этого
существует. С неё стоит начинать разбор любой проблемы установки.

Типовые случаи:

* **`не удалось загрузить библиотеку SQLite`.** Библиотека берётся из
  комплекта (`lib/`), иначе из системы. Linux:
  `apt install libsqlite3-0` / `dnf install sqlite-libs`. Windows: положите
  `sqlite3.dll` в `lib\` рядом с программой (`build.ps1` качает её сам) —
  иначе используется системная `winsqlite3.dll`. Можно указать файл явно:
  `SQLITE_LIBRARY=/путь/к/libsqlite3.so.0`.
* **Порт занят или закрыт.** `PORT` в `config.yaml`; на Windows правило
  брандмауэра создаётся ключом `-OpenFirewall`, на Linux — средствами
  дистрибутива (`firewall-cmd`, `ufw`).
* **Служба не пишет в папку CDI.** Linux: папка должна быть доступна
  пользователю `perechen`; в юните она перечислена в `ReadWritePaths` —
  установщик подставляет туда фактический путь. Сетевую папку Windows
  указывайте UNC-путём, доступным учётной записи SYSTEM (или переведите
  задачу на доменную учётную запись).
* **Расписание сдвинулось.** Не сдвинется: 06:00 и 20:00 считаются по
  московскому времени внутри сервиса, часовой пояс и перевод часов на хосте
  на это не влияют.

## 4. Конфигурация

Параметры читаются из `config.yaml` и переменных окружения; окружение
приоритетнее. Три параметра — адреса первоисточника и папка выгрузки —
дополнительно правятся ответственным на экране «Настройки» (§4.1), и такая
правка приоритетнее всего остального. Файл ищется по `--config`, затем `CONFIG_FILE`, затем в
системном каталоге службы (`/etc/perechen`, `%ProgramData%\Perechen272FZ`,
`/usr/local/etc/perechen`) и рядом с программой. Образец —
[`apps/server/config.example.yaml`](apps/server/config.example.yaml), фактически
использованные значения показывает `perechen paths`.

Значения по умолчанию для каталогов зависят от ОС (см. §3.6); в таблице ниже

### 4.1. Настройки из интерфейса

Экран «Настройки» (шестерёнка в шапке списка версий) позволяет ответственному
самому изменить то, что меняется по ходу эксплуатации, без правки `config.yaml`
и перезапуска службы:

| Настройка | Что задаёт |
|---|---|
| Прямая ссылка на файл (xlsx) | `MINJUST_EXPORT_URL`. Пустая — адрес ищется на странице перечня |
| Страница перечня на сайте Минюста | `MINJUST_PAGE_URL` |
| Проверка сайта | `DOWNLOAD_CRON` |
| Авто-публикация | `AUTO_PUBLISH_CRON` |
| Папка для целевого CSV | `CDI_DROP_DIR` |

Приоритет: **правка в UI → переменная окружения → `config.yaml` → умолчание**.
Правка хранится в БД (таблица `meta`), переживает перезапуск и действует со
следующей загрузки или публикации — пересобирать и перезапускать ничего не
нужно. Рядом с изменённым полем показано значение из конфигурации и кнопка
«Вернуть из конфигурации», которая снимает правку.

Что проверяется при сохранении:

* адреса — схема `http`/`https` и наличие узла; оба адреса пустыми быть не могут;
* расписания — тем же разбором cron, что и в планировщике; под полем сразу
  показано, как выражение прочитано («Запуск по будням в 07:30»);
* папка — полный путь; папка создаётся, если её нет, и в неё пробуют записать
  файл, поэтому недоступная сетевая шара видна сразу, а не в момент публикации.

Изменённое расписание планировщик подхватывает сразу: задачи `download` и
`auto-publish` переключаются на новое время без перезапуска службы.

Отклонённая правка не меняет ничего: ошибка возвращается с указанием поля и
показывается прямо под ним. Каждое изменение попадает в журнал событий
(`settings_changed`) с автором и списком изменённых настроек.

Правка из UI перекрывает конфигурацию: если после неё поменять `config.yaml`
или переменную окружения, действовать будет по-прежнему значение из UI, пока
его не снимут кнопкой «Вернуть из конфигурации». Что используется фактически,
показывает `perechen paths` (пометка «изменена в UI») и `GET /api/settings`.

## 5. Целевой файл

* Имя: `perechen_organizatsij_272_FZ_YYYY_MM_DD.csv`, где дата — **дата
  актуальности данных из ячейки A2**, а не дата выгрузки.
* Кодировка Windows-1251 без BOM, разделитель `;`, перевод строки CRLF в конце
  каждой строки, включая последнюю.
* Первая строка — заголовки, заголовок первой колонки пустой.
* Колонки: `№ п/п`, `Номер и дата распоряжения о включении`, `Реквизиты решения
  Генпрокуратуры о признании`, `Наименование (рус)`, `Наименование (доп.)`,
  `Страна регистрации`, `Номер и дата распоряжения об исключении`, `Реквизиты
  решения Генпрокуратуры об отмене`.
* Значения экранируются по RFC 4180 только при наличии `;`, `"` или перевода
  строки (с записью warning). Символы вне cp1251 заменяются ближайшим
  аналогом (`ä` → `a`, `ß` → `ss`) — тоже с warning.

## 6. Правила разбора наименования

Реализованы все 11 правил п. 6 ТЗ; каждое покрыто отдельным тестом, а
обязательные кейсы п. 6.2 — параметризованным набором в
[`packages/core/test/name_parser_test.dart`](packages/core/test/name_parser_test.dart).

Алгоритм: токенизация строки на кандидатов (текст вне скобок, содержимое
каждой пары скобок, деление по запятым верхнего уровня вне кавычек) →
классификация кандидата (`кириллица` / `латиница` / `страна` / `аббревиатура` /
`служебное` / `иной алфавит` / `география`) → дедупликация подстрок и почти-
дублей → отсев транслита и транскрипции (правила 5 и 6) → выбор самого
длинного кандидата каждого алфавита (правило 11) → очистка кавычек, лишних
пробелов и висящих знаков.

Каждой записи присваивается `confidence`: `ok` или `review`. В `review`
попадают записи, где сработали неоднозначные ветки: отброшен транслит или
транскрипция, несколько равнозначных кандидатов, переименование организации,
фрагменты на ином алфавите, протухшая ручная правка. На эталонном файле из 390
записей `review` получают 21 запись — они подсвечены в интерфейсе.

Справочник стран — редактируемый файл
[`packages/core/assets/countries_ru.txt`](packages/core/assets/countries_ru.txt):
чтобы сервис начал распознавать новое написание страны, достаточно дописать
строку в установленный файл (`/opt/perechen/assets/countries_ru.txt` и
аналогичные, см. `perechen paths`) и перезапустить службу — пересборка
комплекта не нужна.

## 7. REST API

Все методы требуют Basic Auth.

```
GET   /api/health                          состояние сервиса, расписания, последняя проверка
GET   /api/versions                        список версий со счётчиками
GET   /api/versions/{id}                   карточка версии
GET   /api/versions/{id}/records           записи; ?filter=all|new|changed|excluded|review|edited&search=
GET   /api/versions/{id}/export.csv        целевой CSV (предпросмотр/скачивание)
POST  /api/versions/{id}/confirm           подтвердить и опубликовать в CDI
POST  /api/versions/{id}/reparse           перерасбор по сохранённому файлу
PATCH /api/records/{versionId}/{orgKey}    {"values": {...}} — правка, {"revert": ["name_rus"]} — откат
POST  /api/jobs/check-now                  ручная проверка сайта
GET   /api/events                          журнал событий
GET   /api/corrections/{orgKey}            история правок записи
GET   /api/settings                        настройки: адреса, расписания и папка выгрузки
PUT   /api/settings                        правка настроек; поле со значением null — вернуть из конфигурации
```

Ответ `GET /api/settings` по каждой настройке показывает и действующее
значение, и то, что записано в конфигурации:

```json
{
  "minjustExportUrl": {
    "value": "https://reestrs.minjust.gov.ru/rest/registry/1/export",
    "fromConfig": "https://reestrs.minjust.gov.ru/rest/registry/1/export",
    "overridden": false
  },
  "cdiDropDir": {"value": "/mnt/cdi/inbox", "fromConfig": "/mnt/cdi/inbox",
                 "overridden": false},
  "updatedAt": "2026-08-25T12:54:00+03:00", "updatedBy": "admin"
}
```

Ключ записи `org_key` = `{номер распоряжения о включении}__{дата включения в
ISO}`, например `1076-р__2015-07-29`; при пустом номере — SHA-1 нормализованной
сырой строки наименования. Ключ стабилен между версиями, в отличие от № п/п.

## 8. Ручные правки (приоритет человека)

* Правка хранится отдельно от автоматического разбора: `org_key`, поле,
  значение, автор, время и `source_name_hash` — хэш сырой строки наименования
  на момент правки.
* При сборке новой версии правка **перекрывает** автоматический разбор, если
  сырое наименование не изменилось.
* Если наименование изменилось — правка помечается `stale`, применяется
  автоматический разбор, запись получает `confidence = review`, а старое ручное
  значение показывается в интерфейсе рядом для сравнения.
* История правок не затирается: новая правка того же поля делает предыдущую
  неактивной, но обе остаются в таблице `corrections` (полный аудит).

## 9. Эксплуатация

* **Где что лежит.** `DATA_DIR/downloads` — скачанные оригиналы
  (`export_{дата актуальности}_{время}.xlsx`), `DATA_DIR/published` — копии
  опубликованных CSV, `DATA_DIR/perechen.db` — SQLite.
* **Публикация атомарна**: файл пишется во временный файл в папке CDI и
  переименовывается, поэтому скрипт CDI не подхватит недописанный файл.
  Повторная публикация той же версии допустима и идемпотентна.
* **Ошибки.** Не скачалось после ретраев или не распознана структура файла —
  версия помечается `ERROR`, отправляется письмо, ничего не публикуется.
  Недоступность сайта дольше `UNAVAILABLE_ESCALATE_DAYS` суток подряд —
  ежедневное письмо-эскалация.
* **Изменение правил разбора.** Поправить правила в `packages/core`, прогнать
  тесты, затем `POST /api/versions/{id}/reparse` (или
  `dart run bin/server.dart reparse {id}`) — версия пересобирается из уже
  скачанного файла, ручные правки применяются заново.
* **Журнал.** Одна строка — один json-объект. На Linux и macOS его забирает
  система (`journalctl -u perechen -f`), на Windows служба пишет в
  `LOG_FILE` сама, с ротацией по 8 МБ и пятью файлами истории.
* **Миграция на PostgreSQL.** Схема намеренно простая (TEXT/INTEGER, без
  специфичных для SQLite типов); при переходе меняется
  `INTEGER PRIMARY KEY AUTOINCREMENT` на `SERIAL` и реализация в
  [`apps/server/lib/src/db/database.dart`](apps/server/lib/src/db/database.dart).

## 10. Принятые допущения

Ниже — решения по вопросам, которые **не согласованы с заказчиком/вендором**
(раздел 14 ТЗ). Каждое вынесено в конфиг или отдельную стратегию, поэтому смена
поведения стоит одного изменения в одном месте.

| № | Вопрос | Принятое решение | Где менять |
|---|---|---|---|
| Р-1 | Как отражать исключение из перечня | В CSV попадают только строки текущего первоисточника. Если у строки заполнены колонки 7–9 или статус ≠ «Включена» — заполняются целевые колонки 7–8. Исчезнувшие строки в CSV не добавляются: факт фиксируется в БД (`excluded`) и в письме | `ExclusionPolicy` в `packages/core` |
| Р-2 | Формат реквизитов решения Генпрокуратуры | Только дата: `от 28.07.2015` (номеров решения в первоисточнике нет). Исторические `№1 от …` из эталона не воспроизводим | `GP_DECISION_FORMAT=date_only\|with_number` |
| Р-3 | Нормализация страны | Страна пишется как в первоисточнике, без преобразований. Справочник используется только для распознавания | `countries_ru.txt`, `COUNTRY_NORMALIZE=false` |
| Р-4 | Наименование не на кириллице и не на латинице как единственная часть | Оба поля наименования пустые, запись `review`, сырая строка видна в UI | `NameParser`, ветка `other_script` |
| Р-5 | URL экспорта и недоступность сайта | URL из конфига; если не задан — парсинг страницы по селектору. Недоступность > 3 суток подряд — письмо-эскалация. **Проверено 20.08.2026:** на странице Минюста запасной путь не работает — кнопка «Загрузить реестр» имеет `href="#"`, адрес собирается javascript'ом из `ExternalApi.setBaseUrl(...)` и `let id = "..."`. Рабочая прямая ссылка подставлена в `config.example.yaml` | `MINJUST_EXPORT_URL`, `EXPORT_LINK_SELECTOR`, `UNAVAILABLE_ESCALATE_DAYS` |
| Р-6 | Тонкости CSV | Экранирование по RFC 4180 только при `;`, `"` или переводе строки (+warning). Символы вне cp1251 — транслитерация ближайшим аналогом (+warning). Висящие пробелы эталона считаем артефактом: значения `trim()`-аем, двойные пробелы внутри значений схлопываем | `CsvWriter`, `CSV_QUOTE_MODE`, `TRIM_VALUES`, `COLLAPSE_INNER_SPACES` |
| Р-7 | Доступ к UI | Basic Auth из конфига, сервис во внутреннем периметре | middleware в `apps/server/lib/src/api/api_router.dart` |
| Р-8 | Кейс переименования (`с 08.11.2017 – HUMAN RIGHTS PROJECT MANAGEMENT`) | Целевым считаем новое наименование, старое отбрасывается, запись помечается `review` | `NameParser`, ветка `renamed` |

Дополнительные решения, принятые при реализации (за пределами таблицы ТЗ):

* **Часовой пояс** задаётся явным смещением UTC+3 (`Europe/Moscow` без перехода
  на летнее время с 2014 года) — сервис не зависит от настроек хоста;
  планировщик cron-выражений реализован внутри проекта и тикает по МСК.
* **Развёртывание** — системная служба на чистой ОС (systemd, задача
  планировщика Windows от SYSTEM, launchd), а не контейнер: ТЗ предполагало
  Docker, от него отказались. Следствия учтены в коде: нативная библиотека
  SQLite ищется в комплекте и в системе, каталоги данных и конфигурации
  зависят от платформы, журнал умеет писать в файл с ротацией (взамен
  `docker logs`), замена файла в папке CDI переживает блокировку читателем
  на Windows.
* **Чтение xlsx** — собственный минимальный ридер SpreadsheetML (`archive` +
  `xml`) вместо готового пакета: нужен полный контроль над типами ячеек и
  распознаванием даты в A2 по формату стиля.
* **Аббревиатура-исключение**: если после применения правила 9 в классе не
  осталось ни одного кандидата, аббревиатура всё же переносится (иначе поле
  осталось бы пустым), запись помечается `review`.
* **Файл изменился без смены даты актуальности**: если версия ещё не
  опубликована, она пересобирается из нового файла и возвращается в статус
  «ждёт проверки»; если уже опубликована — только событие и письмо.
* **Критерий «содержимое изменилось» — хэш данных, а не байтов файла**
  (`sourceDataHash`: sha256 от построчных `contentHash`). Реестр Минюста
  собирает xlsx на каждый запрос и записывает в `docProps/core.xml` время
  генерации, поэтому sha256 файла различается даже у двух скачиваний подряд —
  проверено 20.08.2026 на трёх выгрузках с интервалом в 3 секунды и 3 дня:
  байтовые хэши разные, хэш данных один. Сравнение по байтам означало бы
  ежедневное ложное «файл изменился без смены даты актуальности» с письмом
  ответственному. `fileSha256` остаётся в событиях для аудита.
* **Ошибочная версия** сохраняется в БД с датой актуальности, равной моменту
  скачивания (настоящая дата неизвестна), чтобы файл и текст ошибки были
  видны в интерфейсе.
